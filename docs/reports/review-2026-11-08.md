## 1. High — Failed CSV import destroys previously stored telemetry

**Location:** `backend/database.py:488–501, 546–550`.

The standard import drops the live telemetry table before validating/inserting the
replacement. There is no encompassing transaction protecting the old table.
`init_db()` runs through a second connection. If later insertion fails, returning
`success: false` does not restore the old data.

**Reproduction:** Start with populated telemetry; import a correctly structured
CSV containing duplicate `event_id` values. Import fails, but the previous table
contents are gone and the telemetry count is zero. Confirmed three times.

**Impact:** `/api/v1/database/sync` exposes this operation on the core database.
An invalid replacement can wipe the existing dataset instead of leaving it intact.

**Fix:** Validate and load into a staging table/database, then replace the live
table atomically after successful loading. Keep schema creation and replacement
on the same explicitly managed connection/transaction. On failure, preserve the
prior data and active-database selection.

## 2. High — Multi-cycle verification reports immunity after failure

**Location:** `backend/agents/adversarial_trainer.py:217–242, 244–257`.

The final verdict is a constant success string. A cycle passes whenever there are
no duplicate successes, including when every request is rejected. Ordinary 400
errors count as successful mitigation; the method never establishes clean,
funded state for the run.

**Reproduction A:** Exhaust the mock campaign budget, then run two cycles with
three streams each. Every cycle approves zero claims but says `PASSED (IMMUNE)`;
the mitigation rate is **150%**, and the final verdict asserts 100% exploit
blocking and zero regression.

**Reproduction B:** Use the existing unlocked claim implementation as an explicit
broken-guard negative control. Two cycles leak four duplicate claims; the final
verdict still says `VERIFIED IMMUNE`. Both cases confirmed three times.

**Impact:** The verification feature cannot reliably distinguish mitigation,
over-blocking, and a breached control.

**Fix:** Initialize independent scenario state while preserving the patch under
test. Require exactly one approved claim per voucher cycle, distinguish guard
rejection from business failure, and derive both cycle and final verdicts from
the measured outcomes. Validate the result using broken-guard and reject-all
negative controls.

## 3. Medium — Valid reordered CSV silently corrupts telemetry fields

**Location:** `backend/database.py:478–501`.

The standard-format check only requires 29 columns, `event_id` somewhere in the
header, and table name `telemetry`. Insertion uses `INSERT INTO telemetry VALUES`
without an explicit column list, so values follow the database schema's order,
not the CSV header order.

**Reproduction:** Swap the CSV's `event_id` and `user_id` columns along with their
values. Import reports success, but the stored `event_id` is `csv-user` and the
stored `user_id` is `csv-event`. Confirmed three times.

**Impact:** Named columns are silently assigned incorrect values. Reordering
numeric/status columns can invalidate classification, financial totals, and RCA;
SQLite's permissive typing does not reliably reject these mistakes.

**Fix:** Require the exact expected unique header set and generate an explicit,
quoted INSERT column list matching CSV order, or normalize each row into the
canonical schema order before insertion. Validate required field types.

## 4. Medium — Investigator excludes newer attacks from its analysis

**Location:** `backend/agents/quant_investigator.py:76–83, 275–283`.

The diagnosis selects the oldest 1,000 events in the requested window. Later
events are silently excluded, yet a negative result describes the window as
nominal without disclosing incomplete coverage.

**Reproduction:** Put 1,000 benign endpoint events followed by five successful
same-user/same-burst claims within 4 ms, all inside a 60-second window. Diagnosis
analyzes only the benign prefix and returns `has_collisions: false`. Confirmed
three times.

**Impact:** An actual recent burst can be missed once the window exceeds the row
cap. At high configured traffic rates, a 60-second window can exceed that cap.

**Fix:** Analyze the complete window using streaming iteration or SQL aggregates.
If sampling is required, disclose truncation and coverage and avoid a clean
window-wide verdict; merely selecting the newest 1,000 still leaves blind spots.

## 5. Medium — Sentinel computes full-window TPS from at most 500 rows

**Location:** `backend/agents/fintech_sentinel.py:81–99, 142–155, 247`.

The query limits the sample to 500 events, but current TPS divides that truncated
count by the full window duration. Financial drain and related forecasts use the
same incomplete sample.

**Reproduction:** With 1,005 events in 60 seconds, Sentinel reports **8.33 TPS**
instead of **16.75 TPS**. Confirmed three times and independently checked against
SQL COUNT over the same window.

**Impact:** Reported TPS cannot exceed `500 / window_seconds`: at 60 seconds it
tops out at 8.33 TPS, so the default 30-TPS ceiling cannot be reached by measured
TPS even if true traffic exceeds it. Other heuristic triggers may still fire.

**Fix:** Compute full-window COUNT and financial aggregates separately from any
bounded detail sample. Use complete-window aggregates for velocity, derivatives,
and forecasts, and disclose the detail sample's coverage.

## Recommended order

1. Make CSV replacement failure-atomic.
2. Correct verification success/failure gates.
3. Correct CSV header-to-column mapping.
4. Correct full-window analysis and Sentinel aggregates.

## Limits

This is a targeted code and offline runtime review, not a guarantee that every
defect has been found. No real-browser interaction/CSP enforcement, external LLM
connectivity, dependency advisory lookup, or million-row load test was performed.
The broken-guard check intentionally substitutes the existing unlocked method;
it demonstrates verifier behavior under a failed control, not spontaneous failure
of the default mock mutex.
